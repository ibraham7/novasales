# التقويم والمواعيد

## ما هو
اجتماعات وعروض ومكالمات ومتابعات مع العملاء. مطفأ افتراضياً لكل مؤسسة؛ يظهر في القائمة بعد أن يفعّله مدير (صفحة `/calendar` ← «تفعيل التقويم»). عند أول تفعيل تُنشأ أنواع اجتماعات افتراضية لتلك المؤسسة فقط.

## الصلاحيات
`calendar.view` (مواعيدي) · `calendar.book` (حجز وتعديل) · `calendar.view_all` (مواعيد الفريق) · `calendar.manage` (إعدادات التقويم). المالك والمشرف لهم الكل، ومشرف القسم: عرض + حجز + مواعيد الفريق، والمندوب: مواعيده وحجزها.

## القواعد (في قاعدة البيانات وتتكرر بالواجهة)
- لا موعدين متداخلين للشخص نفسه عبر كل المؤسسات، والرسالة عامة بلا تفاصيل.
- الدوام: جدول المندوب الخاص إن وُجد وإلا دوام المؤسسة؛ الاستراحات والإجازات؛ بتوقيت المندوب ثم المؤسسة. الأوقات تُخزَّن UTC.
- الحالات: محجوز ← مؤكَّد ← جارٍ ← مكتمل، أو ملغى / لم يحضر (نهائية). النتيجة (تقدّمت / يحتاج متابعة / خسرنا) بعد «مكتمل» فقط ولا تنقل مرحلة الفرصة.

## أين يُحجز
صفحة التقويم، زر «حجز اجتماع» في صفحة الفرصة، وفي المحادثة (مع «اقترح أوقاتاً» الذي يضع نصاً في مربع الرسالة دون إرسال).

## الإعدادات
`/settings/calendar`: دوام المؤسسة والمنطقة الزمنية، أنواع الاجتماعات، جدول المندوب والاستراحات والمنطقة الزمنية الخاصة، والإجازات.

## التصدير
زر «تصدير ICS» في صفحة التقويم: الأوقات UTC، العنوان نوع الاجتماع فقط، بلا اسم العميل ولا هاتفه ولا ملاحظات، والمكان فقط لاجتماعات الرابط والحضوري. الملغى لا يُصدَّر.

## الأتمتة (المرحلة 6)
- **هجرة منفصلة**: `20261123130000_calendar_events.sql` تجعل قاعدة البيانات تسجّل أحداث `calendar.meeting.created / rescheduled / confirmed / completed / cancelled / no_show` في `domain_events` (بلا ملاحظات ولا أرقام؛ مكان الاجتماع فقط لاجتماعات الرابط والحضوري). لا يلتقطها إلا عامل الأتمتة (مطفأ افتراضياً) والأحداث القديمة تُهمل.
- **مشغّلات زمنية**: `time.meeting_starts_in` (قبل الاجتماع بمدة؛ مرة لكل موعد ومدة، ولا تذكير فات وقته عند الحجز) و`time.meetings_digest` (ملخص صباحي لكل مندوب).
- **إجراءان**: `calendar.meeting.confirm` و`calendar.meeting.cancel` (هادئان: ما لا ينطبق يُتخطّى بسبب، لا يفشل المسار).
- **متغيرات الرسائل**: `{meeting_date} {meeting_time} {meeting_type} {meeting_place} {meetings_today}` (بتوقيت المندوب ثم المؤسسة، أرقام لاتينية).
- **9 قوالب جاهزة** في قوالب الأتمتة (كلها تُنشأ مطفأة): تذكير قبل يوم، قبل ساعة، تأكيد بردّ «نعم» (يعمل عندما يكون الاجتماع مرتبطاً بفرصة)، تنبيه المندوب قبل اجتماعه بـ 15 دقيقة، ملخص الصباح، حجز جديد، إلغاء، شكر بعد الاجتماع، متابعة من لم يحضر. رسائل العميل تمر عبر بوابة الإرسال (مفتاح الإرسال ووضع التجربة وساعات الإرسال).
- ردّ «لا» لا يلغي الاجتماع تلقائياً: عدم الردّ بـ «نعم» ينبّه المندوب فقط.

## لاحقاً (غير مبني)
رابط حجز عام يحجزه العميل بنفسه، مزامنة Google/Outlook، قائمة انتظار.
