# تحويلات الإعلانات — المرحلة الأولى

المسار: إعدادات المؤسسة ← تحويلات الإعلانات. الصلاحية: إدارة القمع أو إدارة المؤسسة.

1. اختر الهدف الأساسي: عميل مؤهل (المقترح)، حجز مؤكد، أو بيع ناجح.
2. صنّف مراحل أقماع المؤسسة ثم احفظ. أسماء المراحل لا تحدد التصنيف تلقائيًا.
3. انقل فرصة بين المراحل وافتح سجل التحويلات. لا توجد معالجة رجعية للفرص الحالية.

هذه المرحلة تسجّل النتائج داخل NovaSales فقط. لا توجد اتصالات Google/Meta/TikTok/Snap، ولا تحميل بيانات أو إنشاء جماهير أو إرسال تحويلات. «بانتظار ربط المنصة» حالة داخلية وليست وعدًا بإرسال السجل لاحقًا. الربط والإرسال والموافقة على البيانات خطوات منفصلة لاحقًا.

## الدقة والصلاحيات

التقاط انتقال stage_id/pipeline_id في قاعدة البيانات يشمل القمع والأتمتة التي تستخدم تلك الحقول. التحديث القديم لحقل stage النصي وحده لا يولّد تحويلًا. إعادة الدخول إلى التصنيف المؤهل/الحجز/البيع تُسجل في التاريخ لكنها لا تولّد تحويلًا ثانيًا للفرصة والتصنيف نفسيهما. هذا ليس نظام تحويلات متكررة لكل طلب شراء.

التصنيف «بيع ناجح» يحدده المشرف؛ قيمة الحدث هي قيمة الفرصة وقت الانتقال، وليست إثبات دفع. عند إيقاف التسجيل لا يسجل النظام الانتقالات ولا يستعيدها عند التفعيل. تعديل التصنيف لا يبدل التاريخ. حذف المرحلة أو الفرصة لا يحذف السجلات المرتبطة بها.

جداول التحويلات متاحة لحساب الخدمة فقط، مع RLS وعدم منح المتصفح وصولًا مباشرًا. دوال السيرفر تتحقق من صلاحيات المستخدم ومؤسسته. حفظ إعدادات المراحل عملية واحدة ترفض المرحلة التابعة لمؤسسة أخرى وتمنع التكرار.

## مصدر الإعلان

API إنشاء العميل المحتمل POST /api/v1/leads يقبل attribution اختياريًا إلى جانب بياناته الحالية. يبقى مصادقًا بمفتاح API وصلاحية leads:write؛ المفتاح يُستخدم في سيرفر موقع العميل ولا يُوضع في المتصفح.

الحقول: gclid، gbraid، wbraid، fbclid، ttclid، sc_click_id، utm_source، utm_medium، utm_campaign، consent (unknown/granted/denied). لا يقبل هذا الكائن حقول الهاتف أو البريد. يُنسخ إلى الحدث من العميل المرتبط بالفرصة ومن المؤسسة نفسها.

لم يُركب جمع تلقائي للزيارات: يجب أن يلتقط موقع وصول العملاء معرف الإعلان والموافقة ويرسلهما عبر سيرفره عند إنشاء العميل. لا نستخدم زيارة الموظف داخل CRM كزيارة للعميل. إنشاء العميل يدويًا أو بلا معرف إعلان يبقى بلا إسناد إعلاني. أي إرسال لاحق يجب أن يتحقق من الموافقة وشروط كل منصة ويعالج المحاولات والتكرار.

## الاختبار

npm run build

اختبار SQL الفعلي محليًا عبر PostgreSQL/PGlite دون تعديل عملاء الإنتاج:

```sh
npm install --prefix /tmp/novasales-conversions-db --no-save @electric-sql/pglite@0.3.14
PGLITE_MODULE=/tmp/novasales-conversions-db/node_modules/@electric-sql/pglite/dist/index.js node supabase/tests/crm-conversions.mjs
```

يشمل بدء التسجيل الصريح، تراجع الإعدادات الخاطئة، عزل المؤسسات، نسخ الإسناد، منع تكرار التحويل، إعادة الدخول، تعطيل التسجيل، الاحتفاظ بالتاريخ، وصلاحيات الجداول والدوال.

## نتيجة التحقق

نجح بناء الإنتاج واختبار قاعدة البيانات واختبارات نموذج التحويلات والإسناد الثلاثة. فحص TypeScript الشامل لا يمر بسبب أخطاء موجودة في ملفات أخرى (مثل query-persist وbuyers.functions)؛ لم يبلغ عن أخطاء في ملفات هذه الميزة. لم تُنشأ سجلات عملاء تجريبية في الإنتاج.
